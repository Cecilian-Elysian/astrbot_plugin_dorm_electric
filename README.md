# astrbot_plugin_dorm_electric

宿舍电费余额监控预警插件（AstrBot）。对接学校缴费系统（默认预设：汉江师范学院 `pay2.hjnu.edu.cn` 企业微信缴费接口），绑定一次宿舍即可同时查询**空调费**与**宿舍电费**。

- ⚡ **自动查询**：定时轮询余额，顺带保活 JSESSIONID 会话；凭证失效主动私聊提醒，`/电费 凭证` 一条指令热更新，无需重启
- 🤖 **AI 对话可用**：余额、预警线、播报设置都交给大模型，问一句就能查、能按房间号反查任意宿舍、能引导绑定（[详见](#与-ai-对话)）。绑定/解绑/改绑必须用户亲手回复 6 位确认码才生效，模型无法自己下手
- ⚠️ **低余额预警**：预警线 / 紧急线两级，同会话多费种合并为单条消息，同级冷却 24h；支持「低于 20 再提醒我」的会话级自定义线与随时静音
- ☀️ **每日播报**：早上播报当前余额，24h 内检测到充值会一并提示；可只关播报或全部静音
- 📊 **历史 / 日志 / 自检**：`/电费 历史 [n]` 按天看余额快照（含每日用电与充值）、`/电费 日志 [n]` 看事件流与学校原始返回、`/电费 检查` 一键判定凭证到底生效没有
- 📈 **WebUI 仪表盘**：插件详情页内嵌只读面板（凭证状态、绑定会话一览、余额趋势折线），不回传凭证
- 🔐 **凭证免抓包**：双击 `tools/更新电费凭证.bat` 一键提取并推送（[获取 JSESSIONID](#获取-jsessionid)）

## 快速开始

1. 将本目录复制到 AstrBot 的 `data/plugins/astrbot_plugin_dorm_electric/`，在 WebUI 重载插件（依赖 httpx[socks]、apscheduler 自动安装）
2. **获取凭证**（hjnu 模式必需）：按[获取 JSESSIONID](#获取-jsessionid)操作，拿到后**私聊**机器人发送 `/电费 凭证 JSESSIONID=xxxx`
3. **二选一**完成绑定：
   - **跟机器人聊天**（推荐）：私聊说「我住春雪楼2 八层 A817」，收到 6 位确认码后把数字发回去即可
   - **手动指令**：私聊 `/电费 绑定`，按提示发 `/电费 校区`、`楼栋`、`楼层`、`房间`，最后 `/电费 绑定 1`（自动关联空调费与宿舍电费两个项目下的同一房间）
4. （可选）WebUI 插件配置里调整预警线、轮询间隔、播报时间；想用 AI 对话见[与 AI 对话](#与-ai-对话)

## 获取 JSESSIONID

学校缴费系统只认企业微信里已登录的会话，凭证过期（接口返回 `retcode=91001`）后必须重新获取。**不需要抓包工具，也不需要任何代理中间人**。

### 方式一：一键更新（推荐，WXWork 5.0.11+ 实测可用）

双击 `tools/更新电费凭证.bat`（首次先 `pip install pycryptodome websocket-client`）。脚本自动带调试口重启企业微信（登录态保留）→ 提示你**点开一次**「网上缴学杂费 / 校园一卡通」页面（唯一手动动作）→ 通过 CDP（Chrome DevTools 协议）从 webview 内存读出 `JSESSIONID`，学校验活通过后**自动私聊推给机器人**并回显 → 结束后清理快照并把企业微信还原为普通实例。

机器人地址与账号**不写死在脚本里**，从环境变量读取（未设置则推送前报错）：

```bat
setx ASTRBOT_URL "http://你的服务器:6185"
setx ASTRBOT_USER "你的账号"
```

等价命令行：`python tools/extract_cookie.py --host pay2.hjnu.edu.cn --auto --push`。控制台默认**掩码显示**凭证（只露前 8 位），`--no-mask` 看完整值。

### 方式二：手动提取（老版本企业微信 / CDP 不可用时）

先在 PC 端企业微信里成功打开一次「校园一卡通 / 缴电费」页面让 Cookie 入库（能看到余额即可），再运行仓库内的 `tools/extract_cookie.py`（仅本机运行，插件本身不依赖它）：

```bash
pip install pycryptodome
python tools/extract_cookie.py                      # 列出命中的 cookie
python tools/extract_cookie.py --ready              # 只输出 JSESSIONID=xxx，便于脚本化
```

拿到后**私聊**机器人发送 `/电费 凭证 JSESSIONID=xxxx`，热更新生效不用重启。

> ⚠️ 新版企业微信（5.0.11+）的 Cookie 已写入加密库，纯读库路线失效，只能用方式一；`/电费 凭证` **仅限私聊**（cookie 是全局会话密钥，群聊发送会导致群员互相覆盖）。

## 确认凭证与查询是否生效

`/电费 状态` 里的「凭证：已配置」**只表示值写进了配置，不代表学校认这个会话**。首选 `/电费 检查`，一次给全：凭证状态 + 绑定摘要 + 两个费种的即时查询 + 本会话事件流尾部 5 条。

| 输出 | 含义 | 该做什么 |
|---|---|---|
| `✅ 有效（学校接口已接受本次查询）` | 会话可用 | 无需操作 |
| `⚠️ 学校已拒绝（retcode 91001 会话超时）` | JSESSIONID 过期或写错 | 重新走[获取 JSESSIONID](#获取-jsessionid) |
| `⚠️ 学校接口不可用（网络异常或学校无响应）` | **凭证状态未知**，只是学校没回话 | 稍后重试；学校服务器晚上常抖，别急着重提凭证 |
| `⚠️ 仅部分费种可用` | 一个项目通了另一个没通 | 看明细，多数是两个房间没关联上 |
| `❌ 未配置` | 压根没设 cookie | 私聊发 `/电费 凭证 JSESSIONID=xxxx` |

辅助手段：`/电费 查询` 真实拉一次（报「凭证已失效」即学校拒绝）；`/电费 日志` 能看到学校返回的**原始内容**，是唯一能区分 91001 / 非 JSON / 5xx 的地方；`/电费 状态` 里各费种余额若明显超过 2 倍轮询间隔，说明轮询在静默失败。

> 自检只读不写：不会往历史里塞采样点，敲多少次都不影响 `/电费 历史` 的日均统计。

## 与 AI 对话

v1.1.0 起插件向大模型注册函数工具，让闲聊里就能处理电费。**日常直接聊天即可，下面指令是给 AI 兜底和进阶用的手动入口。**

| 工具 | 作用 | 群聊 |
|---|---|---|
| `dorm_electric_browse` / `dorm_electric_pick` | 逐级浏览学校→校区→楼栋→楼层→房间并选一项（房间层可翻页） | ✅ |
| `dorm_electric_bind_room` | 定位房间并发 6 位确认码：传 `hint`（用户说的房间原话）**不需要逐级浏览**，传 `room_no` 则按 browse 列表选房；已绑定时传不同房间=一步改绑 | ❌ |
| `dorm_electric_unbind` / `dorm_electric_confirm` | 发解绑确认码 / 提交用户回复的确认码 | ❌ |
| `dorm_electric_balance` | 本会话余额 + 是否低于预警线 + 按日均估算还能用几天 + 预警线/播报/轮询配置（可带 `days` 看趋势） | ✅ |
| `dorm_electric_query_room` | **按房间名查任意宿舍**（`春雪楼817` / `A-8-17` / `A817` 全能解析），不需要绑定 | ✅ |
| `dorm_electric_mute_alerts` | 静音/恢复提醒：`hours>0` 静音 N 小时（上限 168）、`0` 查状态、`-1` 恢复；`scope` 选 `alerts`(默认) / `daily` 播报 / `all` | ❌ |
| `dorm_electric_set_alert_threshold` | 本会话自定义预警线：「低于 20 再提醒我」；`warn>0` 设置、`0` 查看生效值、`-1` 恢复全局；`kind` 可只设一种（`ac`/`elec`/`all`，也认「空调」「电费」等中文） | ❌ |
| `dorm_electric_check` | 一次性自检：凭证状态 + 绑定摘要 + 实时查询 + 事件尾部（「凭证还有效吗」） | ✅ |

```
你：可以帮我绑定吗？我住春雪楼2 八层 A817
AI：📍 待绑定：校本部/春雪楼2/8层/A-8-17
    确认码：481526（5 分钟内有效，一次性）      ← 机器人原样发出，避免 AI 复述数字出错
你：481526
AI：✅ 已绑定 校本部/春雪楼2/8层/A-8-17
    空调费 94.66 度、宿舍电费 12.30 元，预警线 10 / 紧急线 5
```

要点：

- **「同意」由插件强制**：确认码必须是用户亲手发回来的——插件在事件级监听原始消息，整条消息里除标点外只剩那 6 位数字才算数（私聊里「确认 481526」「验证码是 481526」也算），群里问「481526 度电够吗」不会误判；AI 自己拿着码调 `confirm` 会被拒绝。验证码 6 位、5 分钟有效、一次性
- **群聊只读**：绑定/解绑/改绑一律引导私聊。群里报房间号可查任意宿舍余额（只返回房间名与余额，不返回内部 ID）——**知情记录**：任何人都能查任何房间
- **绝不猜着办**：房号打错（「A-8-71」）时列出最接近的候选反问，确认前不发码；定位过的房间记 30 分钟，之后只说「绑定」「春雪」这类碎片也能直接办
- **查询类工具不写历史**：AI 反复追问不会稀释「24h 用电 / 日均」统计；房间反查按 `ai_lookup_cache_seconds` 缓存，避免打爆学校接口
- **幕后指令注入**（v1.1.7 起）：聊到电费话题时自动在 system_prompt 追加一段提醒，要求模型必须调工具、严禁编造余额——修掉弱函数调用模型「明明有工具却想不起来用」。纯追加、幂等、不改人格设定，`ai_prompt_hint=false` 可关
- **工具永远不输出凭证值**、学校原始返回、其它会话数据（工具结果会进 LLM 上下文，等于公开）。`ai_tools_enabled=false` 可一键关掉全部工具

### 部署要点

1. WebUI「插件 → 管理行为 → 函数工具」确认 10 个 `dorm_electric_*` 已启用（新增默认启用）；**人格设定的「可用工具」要是「全部」**，白名单模式漏配模型就看不见
2. 主模型必须支持 function calling；不支持时 AstrBot 会自动摘掉工具（模型侧报 `tool call is not supported`），此时 AI 能力不可用但 `/电费` 指令不受影响
3. `/电费 确认 [验证码]` 是 AI 走不通时的兜底（工具被摘、白名单漏配、群聊唤醒规则拦掉纯数字消息时都能用）

### 想让机器人在群里主动开口

属 AstrBot 自身配置（按配置档生效，群聊通常走 `default` 档）：

- `provider_ltm_settings.group_icl_enable` + `active_reply`（`enable` / `possibility_reply` 概率 / `whitelist`）。**注意开 `group_icl_enable` 会把群聊记录注入系统提示词，每轮 prompt 都在变，prompt 缓存失效、token 成本明显上升**
- 主动型 Agent（未来任务，v4.14+ 实验性），OneBot v11（QQ）支持主动推送

## 指令

```
/电费 绑定                启动绑定宿舍向导（自动关联空调费 + 宿舍电费，仅私聊）
/电费 校区 <编号>         选择校区
/电费 楼栋 <编号>         选择楼栋
/电费 楼层 <编号>         选择楼层
/电费 房间                 浏览房间列表（无参翻页，末页回到第 1 页）
/电费 房间 p<页码>         跳到指定页，例如 /电费 房间 p2
/电费 房间 <编号>         按全楼层绝对编号选择房间（不受分页限制）
/电费 绑定 1              确认绑定
/电费 确认 [验证码]       提交 AI 给的确认码；不带参数则查看待确认项（仅私聊）
/电费 静音 [小时]         暂停余额预警：0 或 取消=恢复，N=静音 N 小时（仅私聊）
/电费 预警线 [n]          本会话自定义预警线，两费种同时设（紧急线自动取一半；取消=恢复全局；仅私聊）
/电费 预警线 空调 <n>     只设空调费预警线（「电」或「宿舍电费」=只设宿舍电费）
/电费 解绑                取消监控（仅私聊）
/电费 查询                立即查询空调费 + 宿舍电费
/电费 凭证 <JSESSIONID=xxx> 更新会话凭证（仅私聊，热更新）
/电费 历史 [n]            最近 n 天每日余额快照（默认 7 天，最多 60 天）
/电费 日志 [n]            最近 n 条事件 + 最近一次原始返回（默认 20，最多 100）
/电费 状态                绑定与运行状态
/电费 检查                自检：凭证是否生效 + 绑定是否正确 + 余额能否查到
/电费 帮助                查看帮助
```

> 每个子指令的编号选的是**上一层**选项（`/电费 楼栋 2` 选的是校区）。v1.0.5 起已删除 `/电费 项目`、`/电费 选择`、`/电费 登记`、`/电费 测试`，绑定向导不需要选 aid。

## WebUI 仪表盘（v1.1.7 起）

AstrBot WebUI（v4.6+）打开「插件 → 宿舍电费监控」，详情页内嵌只读面板：顶部卡片（绑定会话数、低于预警线的费种、**凭证状态**、静音数、播报配置）、余额趋势折线（空调费度 / 宿舍电费元，近 14/30/60 天每日快照，缺数据日留空）、绑定会话一览（房间、双费种最新余额按预警线标色、会话自定义预警线与静音状态）。

纯只读（两个 `GET` 接口），**不返回凭证内容**，也不写任何数据；凭证失效时页顶弹红条提示恢复办法。宿主不支持插件 Web 页面时自动跳过注册，旧版 AstrBot 无此入口但不影响其它功能。

## 配置项（WebUI 可视化编辑）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `hjnu_base` | `http://pay2.hjnu.edu.cn` | 学校缴费系统地址，一般无需修改 |
| `hjnu_query_path` | `/wechat/basicQuery/queryElecRoomInfo.html` | 余额查询接口路径 |
| `hjnu_cookie` | 空 | 缴费系统会话凭证（敏感项，面板遮罩显示） |
| `hjnu_user_agent` | 含 `wxwork` 的 UA | 学校会校验 UA 里的 `wxwork` 字样，默认即可 |
| `hjnu_referer` | `/wechat/elecpay/queryelec.html` | 请求 Referer |
| `fee_items` | 汉江师大两项 | 缴费项目 aid → 名称；**顺序有意义**（第 1 项作绑定主 aid，第 2 项自动关联；名称仅用于日志展示） |
| `threshold_warn` / `threshold_critical` | 10 / 5 | 低余额 / 紧急预警线（空调费为度，宿舍电费为元），两费种通用默认 |
| `threshold_warn_ac` / `threshold_critical_ac` | 0 / 0 | 只管空调费的全局预警线/紧急线，0=不启用（沿用通用线） |
| `threshold_warn_elec` / `threshold_critical_elec` | 0 / 0 | 只管宿舍电费的全局预警线/紧急线，规则同上 |
| `alert_cooldown_hours` | 24 | 同级预警重复提醒间隔 |
| `notify_recovery` | false | 余额回升到预警线以上时发送恢复通知 |
| `poll_interval_minutes` | 20 | 轮询间隔（同时保活凭证），0 关闭，最小 5 |
| `daily_report` / `daily_time` / `daily_timezone` | 开 / 08:00 / Asia/Shanghai | 每日播报开关、时间、时区 |
| `request_timeout_seconds` | 15 | 单次查询超时（秒） |
| `http_proxy` | 空 | 留空直连；支持 `http://`、`socks5://` 节点（如 `http://127.0.0.1:7897`） |
| `history_keep_days` | 60 | 历史保留天数（`/电费 历史` 上限同为 60） |
| `ai_tools_enabled` | true | AI 对话工具总开关 |
| `ai_bind_code_ttl` | 300 | 确认码有效期（秒） |
| `ai_lookup_cache_seconds` | 60 | 房间名反查缓存，0 关闭 |
| `ai_prompt_hint` | true | 幕后指令注入开关 |

预警线优先级：**会话单费种 > 会话通用 > 全局单费种 > 全局通用**。
